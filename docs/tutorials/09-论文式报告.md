# 论文式报告写作

## 学习目标

将代码运行记录转换为一份可审查的机器学习项目报告，并把已验证事实与尚未运行的研究计划严格区分。

## 前置条件

- 已完成数据 manifest、配置、指标、checkpoint 和评测日志的归档。
- 已阅读 `docs/paper/README.md` 的章节清单。

## 原理

论文式写作的核心不是术语，而是可追溯主张：每一个模型规模、数据比例、结果数值和结论都应能回到配置、manifest 或 metrics 文件。20 步 demo 只能支持“训练链路与恢复功能已验证”的结论；它不能支持“模型会中文”或“优于英文模型”的结论。

## 执行命令

```bash
python -m pytest tests/test_acceptance.py -v
python -c "from pathlib import Path; print(Path('artifacts/tiny_25m_demo/metrics.jsonl').read_text(encoding='utf-8'))"
```

将实际输出、环境信息和实验表填入报告，而不是凭记忆摘录数值。

## 预期输出

一份包含摘要、问题定义、相关工作、数据、模型、训练、实验、局限性和复现附录的 Markdown 报告。未实际执行的 125M/350M 项目应标为计划，不应伪造结果表。

## 常见故障

- 把 demo 结果称为模型性能结果：应写为“约 30M 配置的 20 步 CPU 链路验收”。
- 未说明许可证：数据章节必须列数据集卡、revision、许可说明与排除规则。
- 只报告最佳生成样例：同时给出 held-out 指标、采样设置、失败案例和运行成本。

## 复现实验证据

附录至少包含命令、Git commit、依赖版本、GPU、随机种子、配置哈希、manifest/tokenizer 哈希、checkpoint URI 和 metrics 文件校验值。
