# 中文预训练先导实验

## 学习目标

在单张 RTX 4090 上，把可追溯的中文公开数据导出为 SinoGPT manifest，训练固定的 50,000 词 BPE tokenizer，并完成约 30M 参数模型的 GPU 冒烟训练和断点恢复。

本章产出的是可观察的预训练 checkpoint，不是具备可靠聊天能力的模型；聊天界面与 SFT 在本章完成后再接入。

## 前置条件

- 已在云端完成 `python -m pytest -q` 的 demo 验收。
- 已进入仓库目录，例如 `/workspace/novel-agent/inbox/SinoGPT`。
- RTX 4090 可用，且 `torch.cuda.is_bf16_supported()` 输出 `True`。
- 预留至少 15GB 可用磁盘。先导数据集用于学习和论文实验，不等于未来商用数据批准。

本教程使用 `agentlans/fineweb2-chinese` 的 `MAINLAND_CHINA` 切片。它的数据集卡标注为 ODC-By，但其上游网页来源仍可能受到原站条款约束；必须保存命令输出中的 revision、许可证说明和统计 JSON。

## 原理

语料导入器不会直接相信数据集分支名，而是先将 `main` 解析为不可变 commit SHA，再把该 SHA 写入每个 manifest 记录。文本经空白标准化、长度过滤与 SHA-256 去重后，依内容哈希稳定地划入训练集或验证集。

在训练 tokenizer 前，词表已经固定 `<|system|>`、`<|user|>`、`<|assistant|>` 三个聊天控制 token。这样后续 SFT 才能使用一致的对话格式；本章训练完成后不得修改这个 tokenizer。

模型每个 optimizer update 实际处理 `4 × 8 × 512 = 16,384` token。100 步约为 1,638,400 token，用来验证数据、bf16、GPU、checkpoint 和恢复；1,250 步累计约为 20,480,000 token，用来观察初步中文续写能力。

## 执行命令

以下命令逐条执行。先更新代码并安装数据导出依赖：

```bash
git pull --ff-only
python -m pip install -e ".[dev,data]"
python -m pytest -q
```

导出 100,000 篇经过长度过滤和去重的中文文档。保留终端打印的 JSON 行；其中 `resolved_revision` 是论文和实验日志所需证据。

```bash
python -m sinogpt.cli.export_hf_dataset \
  --dataset agentlans/fineweb2-chinese \
  --subset MAINLAND_CHINA \
  --revision main \
  --license-note "ODC-By 1.0; research pilot; upstream Common Crawl terms apply" \
  --train-output data/manifests/pilot_train.jsonl \
  --validation-output data/manifests/pilot_validation.jsonl \
  --limit 100000 \
  --min-chars 200 \
  --max-chars 12000 \
  --validation-percent 1
```

使用训练集训练唯一的 tokenizer，并把两份 manifest 编码为固定长度 token 缓存：

```bash
python -m sinogpt.cli.train_tokenizer \
  --manifest data/manifests/pilot_train.jsonl \
  --output artifacts/tiny_30m_pilot/tokenizer.json \
  --vocab-size 50000

python -m sinogpt.cli.prepare_data \
  --config configs/tiny_30m_pilot_stage1.yaml
```

先运行 100 步 GPU 冒烟训练：

```bash
python -m sinogpt.cli.train \
  --config configs/tiny_30m_pilot_stage1.yaml \
  --device cuda
```

确认 checkpoint 存在后，从第 100 步继续到第 1,250 步：

```bash
python -m sinogpt.cli.train \
  --config configs/tiny_30m_pilot.yaml \
  --resume artifacts/tiny_30m_pilot/checkpoints/step_100.pt \
  --device cuda
```

训练完成后，用固定种子观察续写；此时不要期待它成为助手：

```bash
python -m sinogpt.cli.sample \
  --checkpoint artifacts/tiny_30m_pilot/checkpoints/step_1250.pt \
  --prompt "人工智能的发展" \
  --tokens 80 \
  --seed 17 \
  --device cuda
```

## 运行已准备的全部预训练数据

如果已完成 1,250 步，且数据准备阶段打印了 `prepared train_sequences=153019`，可以从已保存的 checkpoint 连续训练至该训练缓存的一次完整覆盖。每次 optimizer update 使用 `4 × 8 = 32` 条、每条 512 token 的训练序列，因此所需总步数是 `ceil(153019 / 32) = 4782`。当前 1,250 步已经处理 20,480,000 token；续训 3,532 步后累计为 78,348,288 token。

不要重新运行 tokenizer、`prepare_data`，也不要把 SFT 的 `best.pt` 作为预训练恢复点。使用下面的配置与预训练 checkpoint：它保持模型、tokenizer、数据、优化器、随机状态和数据游标连续，只把训练的总终点延长到 4,782 步。

```bash
git pull --ff-only

python -m sinogpt.cli.train \
  --config configs/tiny_30m_pilot_fullpass.yaml \
  --resume artifacts/tiny_30m_pilot/checkpoints/step_1250.pt \
  --device cuda
```

该命令会把新的训练指标追加到原有 `artifacts/tiny_30m_pilot/metrics.jsonl`，并新增 1,500、1,750、…、4,750 与最终 `step_4782.pt` checkpoint。若需要停止，等待一个 checkpoint 写入完成；之后用最新 checkpoint 作为 `--resume` 参数并执行同一条命令。

完整覆盖当前 100,000 篇网页文本比 1,250 步试验更有价值，但它仍只是 30M 参数、约 78M token 的学习实验，不足以产生可靠的通用中文聊天能力。完成这一步后应比较固定 prompt 的流畅度；若仍不满足目标，下一阶段应扩充**不重复**的预训练语料，而不是反复循环同一份数据或继续增加 SFT 轮数。

## 预期输出

数据导出命令打印单行 JSON，其中包括 `exported`、`too_short`、`too_long`、`duplicates`、`train`、`validation` 和 `resolved_revision`。训练集和验证集都应有非零文档数。

数据准备命令打印 `prepared train_sequences=... validation_sequences=...`。100 步训练结束时应有：

```text
artifacts/tiny_30m_pilot/metrics.jsonl
artifacts/tiny_30m_pilot/checkpoints/step_100.pt
```

恢复训练后还应有 `step_250.pt`、`step_500.pt`、`step_750.pt`、`step_1000.pt` 和 `step_1250.pt`。`metrics.jsonl` 中的 loss 通常总体下降但允许短期波动；固定 prompt 的输出应从随机 token 逐步变为短中文片段或句子。

50,000 词表的随机初始交叉熵应接近 `ln(50000) ≈ 10.82`。如果第一步 loss 达到数十或数百，说明没有使用 GPT 的小尺度初始化；停止训练，拉取包含该初始化修复的代码后从第 0 步重新运行 100-step 阶段。不要恢复由异常初始化产生的 checkpoint。

## 常见故障

- `No module named datasets`：重新执行 `python -m pip install -e ".[dev,data]"`。
- 导出时连接失败或找不到切片：不要改用来源不明的镜像；记录错误并检查数据集 ID、`MAINLAND_CHINA` 和网络访问。
- `not enough tokens for one input-target sequence`：`--limit` 太小、过滤阈值过高，或验证集比例过大；删除本次生成的 pilot manifest 和缓存后，调整参数再导出。
- `CUDA out of memory`：先不要继续完整训练；保留错误日志，将 `batch_size` 临时降为 2 并重新运行 100 步冒烟阶段。
- `non-finite causal language-model loss`：立即停止；保存日志、checkpoint 路径和 Git commit，不要从该 checkpoint 继续。
- 训练 loss 在同等窗口内没有下降：确认 tokenizer、缓存和配置来自同一次导出，不要只凭单一步 loss 判断。
- 可用磁盘低于 15GB：停止训练，把缓存或旧 checkpoint 移至数据盘后再继续。

## 复现实验证据

保存以下内容到实验记录：导出命令输出的 JSON、两个 manifest 的 SHA-256、tokenizer 的 SHA-256、两份 YAML、Git commit、`metrics.jsonl` 和所有 checkpoint 路径。原始文本、pilot manifest、token 缓存和 checkpoint 均不提交到公共 Git 仓库。
