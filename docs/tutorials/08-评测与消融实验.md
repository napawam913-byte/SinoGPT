# 评测与消融实验

## 学习目标

设计能回答“中文、英文、代码数据配比有什么影响”的评测与消融，而不是只展示一段随机生成文本。

## 前置条件

- 三个 125M 消融运行具有相同 tokenizer、架构、优化规则、训练 token 预算和随机种子策略。
- 评测集与训练 manifest 分离，并有自己的来源、revision、许可证与哈希。

## 原理

固定其他变量后比较 `zh_70_en_20_code_10`、`zh_100` 与 `en_100`，各训练 300M token。中文、英文和代码分别报告 held-out cross entropy/perplexity；再加入人工抽查的事实性、语言一致性与有害/许可证风险记录。主模型 `sino_main_350m` 使用 1B token，但只能在前述证据齐全后开始。

| 维度 | 固定项 | 变化项 |
| --- | --- | --- |
| 架构 | 层数、宽度、头数、上下文 | 无 |
| 训练 | token 预算、学习率、batch、种子策略 | 无 |
| 数据 | 清洗规则、tokenizer、评测集 | 中/英/代码的混合比例 |
| 指标 | 每类 held-out loss、吞吐、峰值显存 | 记录每组结果 |

## 执行命令

为每次运行先创建 run manifest，再执行：

```bash
python -m sinogpt.cli.prepare_data --config configs/ablation_125m.yaml
python -m sinogpt.cli.train --config configs/ablation_125m.yaml
```

仅在 run manifest 的 tokenizer 哈希、数据 manifest 哈希、目标 token 数与 checkpoint URI 均通过校验后，才将 125M 配置由 1 步安全闸门改为正式预算。

## 预期输出

每组运行有独立指标文件、checkpoint、评测表与失败日志。比较表必须报告实际训练 token 数和置信/重复运行策略，不能只挑选最佳样例。

## 常见故障

- 三组 tokenizer 不同：结果不再是纯数据配比消融，必须重做或明确重新定义问题。
- 验证文本混入训练集：停止解释结果，修复 manifest 分割和哈希去重后重跑。
- 代码集许可证不清：移除代码比例并把偏离原配比写入报告。

## 复现实验证据

归档 run manifest、训练/评测 JSONL、配置与代码哈希、数据 revision、每类样本数、硬件利用率和异常记录。
