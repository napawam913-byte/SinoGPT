# 从 25M 教学模型到 350M 主实验

## 学习目标

按照固定的研究闸门完成小模型验证、数据配比消融和 350M 主实验，而不是在数据来源与训练链路未知时直接启动昂贵训练。

## 前置条件

- 完成分词器训练、manifest 审计、数据准备和一次可恢复的微型训练。
- 每个实验拥有固定的 tokenizer SHA-256、dataset manifest SHA-256、Git commit、随机种子、目标 token 数和 checkpoint 归档 URI。
- 云端环境已通过 `01-云端环境.md` 的 CUDA/bf16 检查。

## 原理

模型变大不会自动证明中文更好。这里真正要比较的是在固定架构、固定 token 预算和固定训练规则下，语料配比对中英能力的影响。先验证训练系统再扩大实验，能把“代码错误、数据错误、规模效应”分开。

| 阶段 | 模型 | 数据配比/预算 | 通过条件 |
| --- | --- | --- | --- |
| A | 25M 教学模型 | 仅小型已许可 demo | 20 个有限 loss、可恢复 checkpoint、固定种子样本 |
| B | 125M 消融模型 | `zh_70_en_20_code_10`、`zh_100`、`en_100`，各 300M token | 三组拥有相同 tokenizer、架构、预算和评测集 |
| C | 350M 主模型 | 中文 70% / 英文 20% / 代码 10%，1B token | 溯源完整、消融结果已记录、存储与恢复演练通过 |

当前 `configs/ablation_125m.yaml` 和 `configs/main_350m.yaml` 的 `max_steps: 1` 是安全闸门，不代表真实长训练配置。只有记录了不可变 provenance 后才将它改为经 token 预算换算出的步数。

## 执行命令

先训练 tokenizer 与准备数据：

```bash
python -m sinogpt.cli.train_tokenizer --manifest data/manifests/train.jsonl --output artifacts/tokenizer.json --vocab-size 50000
python -m sinogpt.cli.prepare_data --config configs/tiny_25m.yaml
python -m sinogpt.cli.train --config configs/tiny_25m.yaml
```

从最近 checkpoint 恢复时，必须显式传入：

```bash
python -m sinogpt.cli.train --config configs/tiny_25m.yaml --resume artifacts/tiny_25m/checkpoints/step_250.pt
```

在 125M/350M 开始前，先依据 `docs/experiments/run-manifest-template.json` 创建并校验该实验的 run manifest；不要只通过修改 YAML 直接启动。`sinogpt.experiments.validate_run_manifest` 会拒绝空或格式错误的 tokenizer/数据 SHA-256、空归档 URI、非整数种子和非正 token 预算。

## 预期输出

- 每次训练目录都有 `metrics.jsonl` 和 `checkpoints/step_*.pt`。
- metrics 每行包含 `global_step`、`loss`、`global_grad_norm`、`tokens_per_second`、`peak_memory_bytes` 和 `tokens_seen`。
- 125M 三组实验可在同一评测脚本下并排比较；350M 运行可由 SHA-256 和 checkpoint URI 重新定位。

## 常见故障

- 350M OOM：首先减小 `batch_size`，相应增加 `gradient_accumulation_steps` 保持有效 batch；不要任意改变上下文长度或数据预算后仍把结果称为同一实验。
- loss 曲线不可比：检查 tokenizer、训练 token 数、随机种子、学习率和评测集是否完全固定。
- 代码语料许可证不清：把 10% code 配额重新分给英文，并在 run manifest 说明；不要使用无授权代码填充。

## 复现实验证据

每一行实验表至少记录：run 名称、Git commit、配置文件哈希、tokenizer/manifest 哈希、混合比例、目标与实际 token 数、峰值显存、训练时长、最终 checkpoint URI、评测结果与失败原因。
