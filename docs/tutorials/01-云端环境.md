# 云端环境与项目部署

## 学习目标

在单张 RTX 4090（24GB 显存）、64GB 内存、100GB 系统盘的云端容器上，建立可复现实验环境，并明确哪些文件必须放到对象存储或挂载数据盘。

## 前置条件

- 一台已启动的 CUDA PyTorch 云端实例。你当前选择的 `cuda12_torch2130_py312` 镜像和单 RTX 4090 适合作为本项目的起点。
- 项目目录 `D:\learning\SinoGPT` 的副本：通过 Git、压缩包或平台文件上传功能传到云端。
- 原始数据、处理后的数据和长期 checkpoint 的对象存储或挂载数据盘。100GB 系统盘只保留代码、当前缓存和最近两个 checkpoint。

## 原理

4090 的优势是 24GB 显存与 bf16 支持，但 350M 模型训练仍需要小 micro-batch 与梯度累积。项目会在配置要求 bf16 而设备不支持时直接报错，避免悄悄退化为不受控的精度模式。

训练可恢复的最小状态不是只有模型权重：还包括 AdamW 优化器、学习率调度器、全局步数、数据游标与随机数状态。任何一项缺失都会使恢复后的实验不再与原运行一致。

## 执行命令

在云端终端执行（路径按你的挂载位置替换）：

```bash
cd ~/SinoGPT
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"

python -c "import torch; print(torch.__version__, torch.cuda.get_device_name(0), torch.cuda.is_bf16_supported())"
python -m pytest -v
ruff check src tests
```

将数据盘路径写入 YAML 的 `data.cache_dir`，将长期 checkpoint 存储路径记录在实验 run manifest。不要把未经审计的网页抓取数据直接复制到系统盘并训练。

## 预期输出

- CUDA 检查显示 RTX 4090，且 `torch.cuda.is_bf16_supported()` 为 `True`。
- 单元测试通过，Ruff 显示无静态检查问题。
- `data/cache/` 只包含可重新生成的 token 缓存；训练输出目录中只有当前实验和最近 checkpoint。

## 常见故障

- `CUDA was requested but is not available`：实例尚未启动、容器没有挂载 GPU，或驱动与 CUDA 镜像不匹配。
- `this config requires CUDA bf16 support`：不要强行改为 fp16；先确认 GPU 型号与 PyTorch CUDA 安装，再决定是否选择支持 bf16 的实例。
- 系统盘空间不足：迁移原始语料、数据缓存或历史 checkpoint 到数据盘/对象存储，再重新运行 `prepare_data`。

## 复现实验证据

保存以下文本日志到实验目录：`pip freeze`、CUDA 检查输出、配置 YAML 的 SHA-256、manifest SHA-256、tokenizer SHA-256、Git commit ID 和每次 checkpoint 路径。
