# GPT-3 风格解码器架构

## 学习目标

在不依赖黑盒模型库的前提下，读懂本项目每个参数张量、每层计算以及它们和 GPT-3 论文中 decoder-only Transformer 的对应关系。

## 前置条件

- 已安装项目依赖并通过 `tests/test_model.py` 的基础配置测试。
- 已理解 token ID 与词表大小 `V` 的关系。

## 原理

### 本项目的结构

输入是整数 token 序列 `[B, T]`。Token Embedding 与 Position Embedding 相加后，依次经过 `L` 个 Pre-LN Transformer Block、最终 LayerNorm 和词表投影层，输出 `[B, T, V]` logits。

```text
token IDs → Token Embedding ─┐
                             ├→ x0 → [Pre-LN Block] × L → Final LN → tied LM Head → logits
position IDs → Position Emb. ─┘
```

主实验配置为 `L=24`、`d_model=1024`、`n_head=16`、`d_ff=4096`、上下文长度 1024。它约为 3.5 亿参数，是单张 24GB RTX 4090 上可以通过 bf16 与梯度累积实践的教学规模；它不是 175B 的原始 GPT-3。

### 一个 Pre-LN Block

```text
x ─→ LayerNorm ─→ Causal Multi-Head Attention ─→ (+) ─→ LayerNorm ─→ Linear(d→4d) ─→ GELU ─→ Linear(4d→d) ─→ (+) → y
└─────────────────────────────────────────────────┘                                                              │
                              residual ─────────────────────────────────────────────────────────────────────────┘
```

Pre-LN 表示 LayerNorm 位于子层之前。残差连接使深层网络可直接传递信息和梯度。

### 因果注意力

每个头先由同一个线性层生成 `Q, K, V`。对每个头：

`S = QKᵀ / √d_head`

把上三角（未来位置）的分数置为 `-∞`，再按最后一维 Softmax：

`A = Softmax(mask(S))`，`O = AV`

因此第 `t` 个位置只能使用 `0..t` 的 token，不能看见答案中的未来 token。

### 激活函数：GELU

MLP 严格执行 `Linear(d, 4d) → GELU → Linear(4d, d)`。PyTorch 默认精确 GELU 对应：

`GELU(a) = 0.5a(1 + erf(a / √2))`

GELU 不是 sigmoid 或 ReLU；它会平滑地保留较小的负输入，这也是 GPT-3 设计的一部分。

## 预期输出

测试应证明 logits 形状为 `[B,T,V]`、未来 token 不影响过去 logits、且 GELU 前线性层取得有限反向梯度。

## 常见故障

- `n_embd must be divisible by n_head`：每个注意力头必须有整数维度，修改模型宽度或头数后重新校验。
- `input sequence exceeds block_size`：将长文本在数据准备阶段切分，或选择更大的上下文配置；不要在前向中静默截断训练样本。
